# Diretrizes do Projeto

## Escopo da fase de design

Até autorização explícita, o trabalho deve permanecer nos seguintes domínios:

- conceito;
- worldbuilding;
- narrativa;
- sistemas e regras;
- progressão;
- personagens;
- economia;
- multiplayer;
- estrutura da masmorra;
- conteúdo e identidade.

Não devem ser definidos ou implementados:

- código;
- engine;
- banco de dados;
- protocolo ou arquitetura de rede;
- APIs;
- classes de software;
- infraestrutura;
- arquivos de implementação.

## Processo de decisão

Ao discutir um sistema:

1. Explicar o problema de design.
2. Identificar as decisões relevantes.
3. Apresentar alternativas quando houver escolhas reais.
4. Comparar vantagens e desvantagens.
5. Oferecer uma recomendação como proposta.
6. Registrar como definitivo somente depois da aprovação.

## Princípios de avaliação

Toda proposta deve considerar:

- **Diversão:** a experiência produz decisões e situações interessantes?
- **Clareza:** o jogador entende causas, riscos e consequências?
- **Profundidade:** sistemas simples podem interagir de maneiras relevantes?
- **Cooperação:** a mecânica cria interação significativa entre jogadores?
- **Solo:** continua funcional e satisfatória para uma pessoa?
- **Progressão:** existe sensação clara de crescimento?
- **Replay:** personagens, grupos e mundos produzem experiências diferentes?
- **Escopo:** é razoável para um projeto indie?
- **Pixel art:** pode ser comunicado com legibilidade nessa apresentação?

## Limites de escopo

- O projeto deve evitar transformar cada ideia em um sistema independente de grande porte.
- Propostas devem ser avaliadas mentalmente como simples, moderadas, complexas ou muito complexas.
- Custos altos com pouco valor de gameplay devem ser apontados.
- O mundo exterior permanece principalmente contextual para preservar o foco indie.
- O acampamento de exilados não deve tornar-se uma segunda vila completa.

## Referências

Outros RPGs, jogos cooperativos, dungeon crawlers e histórias de exploração podem ser usados para estudar padrões, mas não para copiar sistemas diretamente.

A identidade deve emergir da combinação:

> vila + famílias + personagens fixos + cooperação + cem andares + progressão coletiva do mundo
